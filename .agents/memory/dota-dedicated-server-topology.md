# Dedicated server is a SEPARATE host from the bot

The Dota 2 dedicated game server runs on its OWN DigitalOcean droplet (Sydney syd1), NOT on the bot/website host. This is the single biggest gotcha — the deploy table in replit.md ("prod host with ~/Dota-Stats-Full + pm2") describes the BOT host, which is a different machine from the game server.

- **Game server droplet**: public IP `134.199.166.223` (`ubuntu-s-4vcpu-8gb-amd-syd1`). Has ONLY the game server — no node, no pm2, no checkout, no `.env`.
  - systemd unit `dota-server.service` → `/opt/dota2/start_server.sh` → dota2 `-dedicated -ip 0.0.0.0 -usercon +sv_hibernate_when_empty 0 +rcon_password "…" +map dota`. `-ip 0.0.0.0` is required so RCON's TCP listener binds publicly; `+sv_hibernate_when_empty 0` stops the empty-server self-quit.
  - Replays at `/opt/dota2/game/dota/replays`.
  - **The game build is SteamCMD app `570` (Dota 2 itself), NOT `1628350`.** `1628350` is "Steam Linux Runtime 3.0 (sniper)" — a runtime tool that's almost always "already up to date", so updating it does NOTHING for the game version. App `570` requires a logged-in account that owns Dota (`+login daburapc2`, anonymous is NOT allowed for 570); cached sentry creds in `/root/.local/share/Steam` make subsequent logins passwordless. Update: `/usr/games/steamcmd +force_install_dir /opt/dota2 +login daburapc2 +app_update 570 validate +quit`. Installed buildid lives in `/opt/dota2/steamapps/appmanifest_570.acf`; reported version in `/opt/dota2/game/dota/steam.inf` (ClientVersion/ServerVersion).
- **Bot host**: public IP `170.64.182.110` (`root@Dota-Stats`, checkout `~/Dota-Stats-Full`, pm2 `oi-bot`, node 20, the live `.env`). All `DEDICATED_SERVER_*` env vars + `pm2 restart oi-bot` belong HERE.

**Why:** the Admin Panel "Test: Provision & Connect" diagnostic + serverReplayFetcher run from the bot host and reach the droplet over the public internet, so `DEDICATED_SERVER_IP` / `_SSH_HOST` must be the droplet's PUBLIC IP, and the droplet's RCON (TCP 27015) + SSH (22) must be reachable from the bot host.

**SSH replay-fetch key**: keypair generated on the bot host at `~/.ssh/oi_replay` (private), its `.pub` appended to the droplet's `/root/.ssh/authorized_keys`. The private key is stored in the bot-host `.env` as `DEDICATED_SERVER_SSH_PRIVATE_KEY="…"` (multiline; dotenv ^17 handles it; ssh2 gets it raw).

**Recurring gotcha**: log line `Version out of date (GC wants NNNN, we are MMMM)` means the droplet game build is behind the live GC, and clients trying to join get a Steam popup **"app id specified by server is invalid"** (NOT a network/port problem — the client reached the server fine). Fix = `app_update 570` (see above), server stopped then restarted. Right after restart the journal can still show stale `6775` lines from the OUTGOING process; the NEW pid logs `SV: Connection to Steam servers successful` + the new `server_version` — trust the newest pid. The watchdog (serverHealthMonitor) with `DEDICATED_SERVER_ALLOW_SSH_RESTART=1` will SSH-restart `dota-server.service` on RCON health failure — it can catch the server mid-restart and momentarily show `ECONNREFUSED` in the diagnostic even though the server is fine seconds later (compare the panel's "checked" time vs the journal's startup time before debugging further).

**RCON / player-count probe (for idle gating)**: RCON is classic Source TCP on `0.0.0.0:27015` (the bot's `rconClient.js` connects to the droplet's PUBLIC IP; loopback `127.0.0.1` works too once the server is fully up — it refuses for a few seconds right after a restart). Password is read live from `start_server.sh` (`+rcon_password "…"`). **A2S_INFO (UDP query) is disabled on this server — it times out**, so use RCON, not A2S. The reliable "is anyone playing" signal is the `status` line `players : N humans, 1 bots` → gate on **`N humans == 0`**; the `1 bot` is the permanent SourceTV (`tv_enable 1`) and `stats`' Players column counts that bot, so `stats` is NOT a reliable idle signal.

**Auto-update-when-idle (every 30 min, only when 0 humans)**: implemented as a droplet-local systemd timer `dota-autoupdate.timer` → oneshot `dota-autoupdate.service` → `/usr/bin/python3 /opt/dota2/auto-update.py`, logging to `/var/log/dota-autoupdate.log`. Script logic: RCON `status` → if humans>0 or unreadable, skip (fail-safe, never restart mid-match); compare installed `appmanifest_570.acf` buildid vs latest public buildid from `steamcmd +login daburapc2 +app_info_update 1 +app_info_print 570` (regex the `"public" { "buildid" "…" }`); only when 0 humans AND buildid differs does it stop→`app_update 570 validate`→start. This is droplet ops, intentionally NOT in the repo.
