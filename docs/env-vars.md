# Environment variables (security-relevant)

Detailed reference for the security- and behavior-relevant environment variables
across both editions. Moved out of `replit.md` to keep the project README lean;
`replit.md` keeps a short index that points here.

- `DISABLE_STEAM` — kill-switch for the Steam/Dota Game-Coordinator connection (both editions). **Currently set to `true` in production — Steam is intentionally OFF until further notice (Aug 2026)** so the bot no longer logs into Steam or sends `gamesPlayed([570])` — the "Dota Bot is now playing Dota 2" presence stops entirely. When `true`, startup skips Steam login (`src/index.js`, `community-edition/src/index.js`) and logs a clear, intentional `[Startup] Steam/Dota intentionally DISABLED (DISABLE_STEAM=true)` line instead of the misleading "credentials not set" warning. Everything that doesn't depend on Steam keeps running: web dashboard, Discord bot, Stripe, the Java replay parser, TrueSkill, schedulers. Steam-dependent surfaces (`/inhouse` lobby flow, friend-lobby auto-detect) fail soft — they report "Steam not connected" and stay dormant rather than crashing. The feature-health `steam_auth` probe returns `ok: 'disabled by env'` so it stays green. **Re-enable** by removing `DISABLE_STEAM` (or setting it to anything other than the exact string `true`) and restarting the process; the underlying reconnect behaviour (task #840) is only relevant once Steam is turned back on. In production each edition is a separate checkout/PM2 process on the prod host (`oi-bot`, `inhouse-bot`) — set the var in that host's environment and `pm2 restart <name> --update-env` for it to take effect there.
- `REPLAY_STORE_DAYS` — Task #856 replay retention. Days to keep stored `.dem` replay files on disk before the 12-hourly sweep deletes them (match rows and parsed stats are always kept). **Default is now `90`** — set any positive integer to change the window, or `REPLAY_STORE_DAYS=0` to explicitly opt in to keep-forever. Replays stored before retention was configured get an expiry backfilled (match date + window, floored at 7 days out so enabling retention never mass-deletes on the next sweep). Companion: `REPLAY_STORE_DIR` overrides the storage directory.
- `ERROR_ALERT_WEBHOOK_URL` — Task #856 error monitoring. Discord/Slack-style incoming webhook that receives alerts from the central error monitor (`src/observability/errorMonitor.js`): uncaught exceptions, unhandled rejections, and Express 500s, each with a request ID and a secret-redacted stack snippet. Falls back to `OWNER_ALERT_WEBHOOK_URL` when unset. Alerts are rate-limited (max 5/min, same-error dedupe 10 min) so an error loop can't flood the channel.
- `STRIPE_INBOX_STUCK_MINUTES` — Task #897 payment-webhook failure alerting. The Stripe webhook pipeline now pages the owner webhook (`ERROR_ALERT_WEBHOOK_URL`, falling back to `OWNER_ALERT_WEBHOOK_URL`) the moment it starts breaking: signature rejects and handler errors on `/api/stripe/webhook`, repeated inbox retry-sweep failures, and a 15-minute stuck-inbox watchdog that alerts when inbox rows sit failed or unclaimed past a threshold (`src/observability/paymentAlerts.js`). This var sets that stuck threshold in minutes (default `30` — two retry-sweep cycles plus slack, so a transient failure that heals itself stays quiet; first watchdog check is delayed 10 min after boot). All alerts funnel through the central error monitor, so they inherit its rate limiting (max 5/min) and per-signature dedupe (10 min) — a webhook error loop can't flood the channel.
- `STARTUP_ALLOW_MISSING_ENV` — Task #856 fail-fast escape hatch. In production (`NODE_ENV=production`) startup now refuses to boot when a critical env var is missing (`DATABASE_URL`, `SESSION_SECRET` 32+ chars, `DISCORD_TOKEN`, `STEAM_ACCOUNT`/`STEAM_PASSWORD` unless `DISABLE_STEAM=true`, `STRIPE_SECRET_KEY`). List intentional omissions comma-separated here (e.g. `STARTUP_ALLOW_MISSING_ENV=STRIPE_SECRET_KEY`) to downgrade them to a warning.
- `HEALTH_URL` / `HEALTH_TIMEOUT` — Task #856 deploy gate. `deploy.sh` polls `HEALTH_URL` (default `http://127.0.0.1:${PORT:-5000}/api/health`) after the PM2 restart until it reports `ok:true`, failing the deploy loudly (with recent PM2 logs) after `HEALTH_TIMEOUT` seconds (default 120).
- `PUBLIC_HEALTH_URL` / `PUBLIC_HEALTH_TIMEOUT` — Task #895 public-URL deploy gate. After the local health check passes, `deploy.sh` also probes the public health endpoint so a DNS/proxy/TLS breakage can't pass on localhost alone. The probe runs automatically when the app is a production deploy — `NODE_ENV` and `CANONICAL_HOST` are read from the PM2 process env (authoritative, like `PORT`), falling back to the deploy shell — defaulting to `https://<CANONICAL_HOST or oceinhouse.gg>/api/health`. Set `PUBLIC_HEALTH_URL=<url>` to override, or `PUBLIC_HEALTH_URL=skip` to bypass (lab hosts). Wall-clock timeout via `PUBLIC_HEALTH_TIMEOUT` (default 60s). On failure the deploy exits non-zero with a note that the process itself is healthy — check DNS/proxy/cert before rolling back code.
- `DEPLOY_REF` — Task #895 rollback support. `deploy.sh` normally deploys `origin/main`; set `DEPLOY_REF=<sha-or-ref>` to pin the deploy to an exact commit for a rollback (`DEPLOY_REF=<previous-good-sha> bash deploy.sh`). All hard gates still run. See `docs/go-live-checklist.md` § Rollback.
- `BACKUP_RCLONE_REMOTE` / `BACKUP_LOCAL_DIR` / `BACKUP_KEEP_DAILY` / `BACKUP_KEEP_WEEKLY` / `BACKUP_ALLOW_LOCAL_ONLY` — Task #896 nightly off-host database backups. A node-cron job (02:30 Australia/Sydney, `src/jobs/nightlyDbBackup.js`) takes a full `pg_dump -Fc` of `DATABASE_URL` into `BACKUP_LOCAL_DIR` (default `~/backups/nightly`), prunes to the newest `BACKUP_KEEP_DAILY` (default 14) daily + `BACKUP_KEEP_WEEKLY` (default 8) Sunday dumps, then `rclone sync`s the dir to `BACKUP_RCLONE_REMOTE` (e.g. `oi-backups:oi-db-backups/nightly` — any rclone backend: Spaces/S3/B2/sftp). Failures ping `ERROR_ALERT_WEBHOOK_URL` and flip the `nightly_db_backup` cron heartbeat to `error`; **in production an unset `BACKUP_RCLONE_REMOTE` is itself alerted nightly** unless `BACKUP_ALLOW_LOCAL_ONLY=1` explicitly accepts local-only dumps. Manual end-to-end run / restore drill: `node scripts/run-db-backup.js`; full setup + tested restore procedure in `docs/db-backups.md`. Binary overrides: `BACKUP_PG_DUMP_PATH`, `BACKUP_RCLONE_PATH`.
- `OWNER_DISCORD_ID` — overrides the hardcoded Discord owner ID used by `!perf-backfill`, `!backfill-pick-source`, and other owner-only Discord commands in both editions (`src/discord/bot.js`, `community-edition/src/discord/bot.js`). Falls back to the historical default (`135991380760592384`) when unset so prod doesn't break on a missed env update — set this in Replit secrets / prod env any time the owner handle changes.
- `OTEL_EXPORTER_OTLP_ENDPOINT` — Task #417 observability gate. When **unset**, OpenTelemetry stays fully disabled (no SDK, no exporter, no perf cost). Set to the Grafana Cloud OTLP/HTTP base URL (e.g. `https://otlp-gateway-prod-us-east-0.grafana.net/otlp`) to enable HTTP + Express auto-instrumentation, plus custom spans/metrics on the parser, Stripe SDK, dedicated-server provisioner, Discord sends, replay download, and push delivery. Companion vars: `OTEL_EXPORTER_OTLP_HEADERS` (e.g. `Authorization=Basic <base64(instanceID:token)>`), `OTEL_SERVICE_NAME` (defaults to `oi-bot`), `OTEL_METRICS_EXPORT_INTERVAL_MS` (defaults to `30000`). Dashboard JSON committed at `ops/grafana/dashboard.json` — import it via Grafana → Dashboards → New → Import.
- `attached_assets/*.json|*.pem|*.key` are now `.gitignore`-blocked after Task #362's leaked GCP service-account incident. Don't bypass; if a JSON dump genuinely needs to be in-tree, scrub the secrets first.
- `FULL_SITE_LOCKDOWN` — Task #493 owner-only login gate for the full edition (`oceinhouse.gg`). **Unset** (default) means the gate falls through to the DB-backed runtime toggle from Task #497 (default: off). Set to `1` to **force the gate ON regardless of the AdminPanel toggle** — useful as an emergency lock or for the initial deploy before the DB row exists. Behavior when the gate is on: unauthenticated HTML navigations get an inline sign-in page (no app HTML, no meta description, no OG tags); non-HTML requests get a 401 with an empty body. Allowlist (always works): `/api/stripe/webhook`, `/api/admin/superuser-login`, `/auth/steam`, `/auth/steam/return`, `/api/auth/complete`, `/robots.txt`, `/favicon.ico`. Successful superuser login (session cookie OR `x-superuser-key` header) bypasses the gate. **Day-to-day, prefer the AdminPanel toggle** (Overview tab → "🔒 Site lockdown" card) which flips the gate live without a restart — the env var is the fallback / override. Community edition (`dota.stats.corvidaeinc.com`) is untouched.
- `SESSION_FINGERPRINT_SALT` — Task #431 smurf-detector fingerprint signal. Optional. The session middleware in `src/web/sessionFingerprint.js` stamps `sess.ip` + `sess.ua` as salted-SHA-256 hashes truncated to 16 hex chars so the smurf scorer can detect two accounts signing in from one machine. Falls back to `SESSION_SECRET` when unset (same trust boundary as the cookie signature). Rotating this value effectively forgets all stored fingerprints on next login. Privacy posture: raw IP / UA never hit the DB; only the hash is stored on the `user_sessions.sess` JSONB; retention is bounded by the 7-day cookie maxAge plus connect-pg-simple's pruner — there is no separate long-lived audit log. Only authenticated sessions are stamped; anonymous visitors leave nothing behind. The hash is re-written at most once every 15 minutes per session or immediately when the hashed IP/UA changes (the case the smurf scorer cares about).
- `SESSION_COOKIE_DOMAIN` / `CANONICAL_HOST` — Task #661 apex↔www session persistence (full edition only; community untouched). The live full site is reachable on both `oceinhouse.gg` and `www.oceinhouse.gg`; a host-only `oi.sid` cookie meant a sign-in on one host wasn't sent on the other, so a refresh that drifted hosts came back signed-out. **`SESSION_COOKIE_DOMAIN`** sets the session cookie's `Domain` so `oi.sid` spans the apex + every subdomain. **Unset** defaults to `.oceinhouse.gg` *only when `NODE_ENV=production`* (so dev/preview on `*.replit.dev` keeps a host-only cookie — a non-matching Domain makes the browser silently reject the Set-Cookie and nobody can sign in). Set to `none`/`host-only`/`off` to force the legacy host-only cookie. **`CANONICAL_HOST`** (defaults to `oceinhouse.gg` in prod, unset elsewhere) drives a 301 that settles `www.<host>` navigations on the bare apex so the two never diverge; only GET/HEAD are redirected and `/auth/steam/return` + `/api/stripe/webhook` are skipped (signature- and POST-sensitive). `/api/auth/me` and the SPA HTML shell are also marked `no-store` so no upstream proxy can serve a stale signed-out reload.
- `BRAND_ASSET_REFERER_ALLOWLIST` — Task #491 brand-asset hotlink protection (full edition only; community untouched). Comma-separated list of extra referer host suffixes that are permitted to load our **distinctive** brand assets (`/oa-logo.png`, `/favicon.png`, `/favicon.ico`, `/badges/*`, `/voice-packs/*`, `/sounds/*`, scoreboard renders `*/recap-card.png` + `/overlay/scoreboard/*`). The middleware in `src/security/assetHotlink.js` (mounted just before the static handler in `src/web/server.js`) inspects the `Referer` header: empty/unparseable referer, same-origin, our built-in domains (`oceinhouse.gg`, `dota.stats.corvidaeinc.com`, `corvidaeinc.com`, `localhost`, `replit.dev`, `repl.co`, `replit.app`), and known social unfurlers (Discord/Twitter/Slack/Telegram/etc. by UA) are allowed; anything else gets a 403 text body. Generic bundled assets (JS/CSS/fonts, the Dota minimap, `sw.js`, `robots.txt`) are NOT gated. Every decision (allowed/blocked) is recorded into an in-memory ring buffer (5000 cap, no schema). The admin "Brand-asset hotlinks" card in the full-edition AdminPanel (Overview tab) renders the aggregated report grouped by referer host via `GET /api/admin/asset-hotlink-report` (superuser). Set this var to add partner domains that should be allowed to embed our imagery.
- `SUPERUSER_STEAM_IDS` — **password-free, Steam-account-bound superuser** (full edition only; community untouched). Originally the Task #749 binding *added on top of* `SUPERUSER_PASSWORD`; the browser password has since been **removed entirely** — superuser access in the web app is now **purely** a function of "are you signed in with a Steam account on this allow-list". Comma/space/newline-separated list of **Steam 32-bit account ids** (the value stored on `req.session.accountId`). Helpers in `src/web/server.js`: `parseSuperuserSteamIds()` + `isAllowlistedSteamSuperuser(req)`; both `getEffectiveRole()` and `requireSuperuser()` auto-grant superuser to an allow-listed Steam session, so an allow-listed owner is superuser **automatically on sign-in** — `/admin/session-status` reports `isSuperuser:true`, the crown shows "👑 Admin", and the modal (now a password-free "Continue as superuser" confirm) is rarely needed. The owner's account id (`35944021`) is a **hardcoded always-included default** (`DEFAULT_OWNER_STEAM_ACCOUNT_ID` in `src/web/server.js`, mirroring the `OWNER_DISCORD_ID` fallback in `src/discord/bot.js`): it is added to the allow-list on top of whatever the env var lists, so the owner gets past the lockdown gate and into the admin panel **even when `SUPERUSER_STEAM_IDS` is unset/typo'd** — a missing env var can no longer hard-lock the owner out. For *everyone else* the browser path still **fails closed** when their id isn't listed, so set `SUPERUSER_STEAM_IDS` only to add co-owners. Browser failures: not signed in → 403 "Sign in with Steam first…"; signed in but not allow-listed → 403 "not permitted". **`SUPERUSER_PASSWORD` is now OPTIONAL and automation-only**: when set, the `x-superuser-key: <SUPERUSER_PASSWORD>` header still elevates scripts/deploy hooks/the browser-smoke runner (honored by `getEffectiveRole`/`requireSuperuser` and by `POST /api/admin/superuser-login` for the smoke runner's session flip). The web client never sends this header, so the header path doesn't reintroduce a user-facing password. To enable: find your account id (the numeric id in your `/profile` URL / session), set `SUPERUSER_STEAM_IDS=<your id>` (add more ids comma-separated for co-owners), then restart.
- `BLOCK_AI_AGENTS` — Task #492 AI scraper / clone-builder hardening. **Unset** (default) means "observability only": the UA classifier in `src/security/agentClassifier.js` still records every classified agent hit into the in-process ring buffer (5000 cap), still applies the stricter `(ip, ua-family)` rate-limit bucket (custom `handler` flips the entry's decision to `throttled` before returning 429), still DMs the bot owner on first-seen-per-24h, and the X-Robots-Tag + `<meta name="robots" content="noai, noimageai">` are still emitted — but classified agents are NOT hard-blocked. Set `BLOCK_AI_AGENTS=1` to return a 403 with a short policy message for any UA matching `ai-crawler` or `app-builder` in the registry. `unknown-bot` is never hard-blocked (observability only). The classification source-of-truth is `src/security/agentUaList.js`; `web/public/robots.txt` and `community-edition/web/public/robots.txt` are **generated** from it via `node scripts/build-robots-txt.js` (drift gate: `npm run check:robots`). The admin "AI agent traffic" card in the full-edition AdminPanel (Overview tab) renders the live aggregated report (decisions: blocked / throttled / logged) via `GET /api/admin/agent-traffic-report` (superuser).
- `CSP_REPORT_ONLY` / `CSP_REPORT_URI` — Task #750 Content-Security-Policy (full edition only; community untouched). Helmet's CSP is now **on and enforcing by default** — the directives live inline in `src/web/server.js` just after `createServer()` (a per-request nonce middleware runs immediately before the `helmet()` call so the nonce is available when the header is built). Allow-list summary: `script-src 'self' '<nonce>'` (the built SPA is all external modules; the only inline script is the `FULL_SITE_LOCKDOWN` gate page, which carries the nonce — there is **no** `'unsafe-inline'`/`'unsafe-eval'` for scripts); `style-src 'self' 'unsafe-inline' fonts.googleapis.com` (React renders via style attributes); `font-src 'self' data: fonts.gstatic.com`; `img-src 'self' data: blob: https:` (Steam/OpenDota/Twitch CDNs + arbitrary user-supplied coach/sponsor logos — images can't execute); `connect-src 'self' api.opendota.com` (same-origin API + EventSource live-queue/spectate streams, plus the Record-Match hero list); `media-src 'self' data: blob: https:` (same-origin walkthrough mp4 + sound/voice-pack clips today, but the tutorial URL is operator-swappable to an external hosted file); `frame-src 'self' player.twitch.tv www.twitch.tv www.youtube.com www.youtube-nocookie.com player.vimeo.com checkout.stripe.com`; `worker-src 'self'` (web-push service worker); `frame-ancestors 'self'` + `form-action 'self'` + `object-src 'none'` + `base-uri 'self'` + `upgrade-insecure-requests`. **The per-route `frame-ancestors *` override on `/embed/player/:steamId` is preserved** — that handler sets its own `Content-Security-Policy: frame-ancestors *` (and removes `X-Frame-Options`) so the embeddable player card can be framed anywhere. Set **`CSP_REPORT_ONLY=1`** to emit the policy as `Content-Security-Policy-Report-Only` instead (browser logs violations but blocks nothing) for a production soak before trusting enforcement — also the instant rollback if a future change trips the policy, no redeploy needed. **`CSP_REPORT_URI`** (optional) adds a `report-uri` directive so report-only violations are POSTed somewhere collectable. When adding a new external script/embed/connection origin, widen the matching directive here or it will be silently blocked.
